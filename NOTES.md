# MacShade – development notes

See [README.md](README.md) for usage. These notes describe how it works and which pitfalls cost time.

## Architecture in one sentence
The unmodified ReShade 6.8 core (`reshade/`) runs as `libmacshade.dylib` inside an ad-hoc re-signed copy of the game (`DYLD_INSERT_LIBRARIES`);
`mac/platform/*` replaces everything Windows-specific.

## Building blocks (`mac/platform/`)
- `dll_main_mac.cpp` + `late_init_mac.cpp`: paths (early, in the first object file), log/config (late, in the last object file) — **link order matters**.
- `vk_loader_emulation.cpp`: plays the Vulkan loader (layer chain, dispatch keys for instance/device/queue/command buffer) and replaces ~140 MoltenVK symbols by
  jump stubs via dyld interposing (`vk_stub_list.inc`, generated by `gen_vk_stubs.py`) and `dlsym`.
  Note: dyld also applies interposing to `dlsym` results — fetch the real functions through `vk_icdGetInstanceProcAddr`, never through `dlsym("vkGetInstanceProcAddr")`.
- `input_mac.mm`: swizzles `-[NSApplication sendEvent:]` → Windows VK key state, mouse position in pixels, cursor capture, GameController.
  Only keys that are ReShade shortcuts wake the bridge from idle (otherwise every WASD press would flash ReShade's own FPS counter).
- `gl_bridge_mac.mm` / `metal_bridge_mac.mm` / `vk_bridge_mac.cpp`: bridge for OpenGL/Metal (IOSurface ↔ private Vulkan device; ReShade's back buffer is replaced via
  `swapchain_impl::_override_image`, then `reset_effect_runtime`/`init_effect_runtime`). The bridges switch themselves off as soon as the app uses Vulkan directly.
  - *Pipelined mode*: ring of 3 IOSurfaces, GL fences (APPLE_fence on legacy contexts, `glFenceSync` on core profiles — the core path is untested), result shown two frames late.
  - *Idle bypass*: with no active effect, closed overlay and no statistics, the bridge leaves the game's frame alone and draws its own FPS counter.
  - *Depth*: OpenGL — the game's scene FBO is found, copied into an R32F IOSurface; Metal — depth attachments are remembered and converted. ReShade sees the "DEPTH" semantic
    (`g_macshade_depth_srv` overrides the built-in depth add-on). The OpenGL search takes the smallest matching framebuffer below ID 128 — only validated with UT2004.
- `frame_limit_mac.cpp`: optional frame limiter (`MACSHADE_FPS_LIMIT`).
- `dll_resources_mac.mm` + `localization_data.inc` (`gen_strings.py`): embedded shaders/fonts/texts, 16 languages (system language automatically).
- `compat/mac_compat.h`: Win32 shims, type-unique `__uuidof` (ReShade uses it as a key for private data!).
- `debug_mac.cpp`: `MACSHADE_CRASH_TRACE` (backtrace even for games with their own crash handler).

## Pitfalls
- A game seems to hang: the macOS "restore windows" dialog after an aborted test → pass `-ApplePersistenceIgnoreState YES` (the launcher does).
- A game seems to hang at start: an unanswered macOS permission prompt (e.g. screen recording) can block it.
- Objective-C objects in globals without ARC → use-after-free (the bridge files are built with `-fobjc-arc`).
- Hardened runtime blocks injection → always run an ad-hoc signed copy; some games (Quetoo) restore their original signature, so the launcher re-checks before every start.
- Tests: never kill a game you did not start yourself (`work/fps_test.sh` only kills its own process and refuses to run while the game is already running).
  Never take full-screen screenshots (private content): use `work/winid2.swift <name> <pid>` + `screencapture -l`.
- lldb attach/launch hangs on this setup and leaves `debugserver` processes → use `MACSHADE_CRASH_TRACE` and the crash reports in `~/Library/Logs/DiagnosticReports`.
- `CRT.fx` (SweetFX) with *Curvature* on renders black through MoltenVK — the Retro presets keep curvature off.

- Quake3e's Vulkan renderer (`quake3e-vulkan`) runs on MoltenVK without ReShade, but with ReShade attached `vkQueueSubmit` returns `VK_ERROR_DEVICE_LOST` right after start, even with no technique enabled. Its OpenGL build works through the bridge. Not investigated further (suspects: the immediate command list flush in ReShade's `vkQueueSubmit` hook, device creation extras).

## Open points / ideas
- Games with a statically linked MoltenVK (Raze): the Metal hook would have to handle `-[CAMetalDrawable present]` including command-buffer synchronisation.
- Depth for OpenGL/Metal on more games; real Metal depth from a game is still unverified.
- Gamepad (GameController) and fullscreen cursor capture are untested with real hardware.
- Core-profile OpenGL (`glFenceSync` path) is untested.
