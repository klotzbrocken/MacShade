# MacShade – development notes

See [README.md](README.md) for usage. These notes describe how it works and which pitfalls cost time.

## Architecture in one sentence
The unmodified ReShade 6.8 core (`reshade/`) runs as `libmacshade.dylib` inside an ad-hoc re-signed copy of the game (`DYLD_INSERT_LIBRARIES`);
`mac/platform/*` replaces everything Windows-specific.

## Building blocks (`mac/platform/`)
- `dll_main_mac.cpp` + `late_init_mac.cpp`: paths (early, in the first object file), log/config (late, in the last object file) — **link order matters**.
- `vk_loader_emulation.cpp`: plays the Vulkan loader (layer chain, dispatch keys for instance/device/queue/command buffer) and replaces ~140 MoltenVK symbols by
  jump stubs via dyld interposing (`vk_stub_list.inc`, generated by `gen_vk_stubs.py`) and `dlsym`.
  Note: dyld also applies interposing to `dlsym` results — fetch the real functions through `vk_icdGetInstanceProcAddr`, never through `dlsym("vkGetInstanceProcAddr")`.
- `input_mac.mm`: swizzles `-[NSApplication sendEvent:]` → Windows VK key state, mouse position in pixels, cursor capture, GameController.
  Only keys that are ReShade shortcuts wake the bridge from idle (otherwise every WASD press would flash ReShade's own FPS counter).
- `gl_bridge_mac.mm` / `metal_bridge_mac.mm` / `vk_bridge_mac.cpp`: bridge for OpenGL/Metal (IOSurface ↔ private Vulkan device; ReShade's back buffer is replaced via
  `swapchain_impl::_override_image`, then `reset_effect_runtime`/`init_effect_runtime`). The bridges switch themselves off as soon as the app uses Vulkan directly.
  - *Pipelined mode*: ring of 3 IOSurfaces, GL fences (APPLE_fence on legacy contexts, `glFenceSync` on core profiles — the core path is untested), result shown two frames late.
  - *Idle bypass*: with no active effect, closed overlay and no statistics, the bridge leaves the game's frame alone and draws its own FPS counter.
  - *Depth*: OpenGL — the game's scene FBO is found, copied into an R32F IOSurface; Metal — depth attachments are remembered and converted. ReShade sees the "DEPTH" semantic
    (`g_macshade_depth_srv` overrides the built-in depth add-on). The OpenGL search takes the smallest matching framebuffer below ID 128 — only validated with UT2004.
- `frame_limit_mac.cpp`: optional frame limiter (`MACSHADE_FPS_LIMIT`).
- `dll_resources_mac.mm` + `localization_data.inc` (`gen_strings.py`): embedded shaders/fonts/texts, 16 languages (system language automatically).
- `compat/mac_compat.h`: Win32 shims, type-unique `__uuidof` (ReShade uses it as a key for private data!).
- `debug_mac.cpp`: `MACSHADE_CRASH_TRACE` (backtrace even for games with their own crash handler).

## Pitfalls
- A game seems to hang: the macOS "restore windows" dialog after an aborted test → pass `-ApplePersistenceIgnoreState YES` (the launcher does).
- A game seems to hang at start: an unanswered macOS permission prompt (e.g. screen recording) can block it.
- Objective-C objects in globals without ARC → use-after-free (the bridge files are built with `-fobjc-arc`).
- Hardened runtime blocks injection → always run an ad-hoc signed copy; some games (Quetoo) restore their original signature, so the launcher re-checks before every start.
- Tests: never kill a game you did not start yourself (`work/fps_test.sh` only kills its own process and refuses to run while the game is already running).
  Never take full-screen screenshots (private content): use `work/winid2.swift <name> <pid>` + `screencapture -l`.
- lldb attach/launch hangs on this setup and leaves `debugserver` processes → use `MACSHADE_CRASH_TRACE` and the crash reports in `~/Library/Logs/DiagnosticReports`.
- `CRT.fx` (SweetFX) with *Curvature* on renders black through MoltenVK — the Retro presets keep curvature off.

- Quake3e's Vulkan renderer (`quake3e-vulkan`) runs on MoltenVK without ReShade, but with ReShade attached `vkQueueSubmit` returns `VK_ERROR_DEVICE_LOST` right after start, even with no technique enabled. Its OpenGL build works through the bridge. Not investigated further (suspects: the immediate command list flush in ReShade's `vkQueueSubmit` hook, device creation extras).

## Open points / ideas
- Games with a statically linked MoltenVK (Raze): the Metal hook would have to handle `-[CAMetalDrawable present]` including command-buffer synchronisation.
- Depth for OpenGL/Metal on more games; real Metal depth from a game is still unverified.
- Gamepad (GameController) and fullscreen cursor capture are untested with real hardware.
- Core-profile OpenGL (`glFenceSync` path) is untested.

## Vulkan apps that bundle the real loader (Spider-Man: Edge of Time recomp)
Apps that ship `libvulkan.1.dylib` + MoltenVK as an ICD (volk, plume) never expose MoltenVK to `dlsym`, so the emulated loader had nothing to hook. `my_dlsym` now also serves `vk*` lookups from a real loader through the emulated one, and `ensure_mvk` loads our own MoltenVK (`MACSHADE_MOLTENVK`) when no ICD is loaded yet. Result: ReShade overlay and effects work in the unmodified (ad-hoc re-signed) copy. Verified only with EdgeOfTimeRecomp 1.0.0 on an M5.

## Screen filter mode (capture_filter_mac.mm)
Opt-in per game (`Game.captureMode`). `Launcher.startFiltered` opens the original app through `NSWorkspace` and starts `MacShadeFilter` (`App/Helper/MacShadeFilter.m`, a few lines that `dlopen` libmacshade and call `macshade_filter_main`). The helper captures the game's window with an `SCStream` (BGRA IOSurfaces), blits each frame into a private work surface, runs `macshade_bridge_process` on it, copies the finished frame into one of five display surfaces that the window server is not using (`IOSurfaceIsInUse`) and sets that as `contents` of a borderless window on the game window's frame (polled four times a second, one level above the game's own window level).
Lessons: (1) never process in place in a surface that may be on screen: that showed unfiltered frames between filtered ones (flicker, menu appearing and vanishing; measured with a test window: 15 of 40 captures filtered before, 40 of 40 after). (2) keep the chosen game window while it exists and debounce restarts: games have several windows, switching restarts the capture and rebuilds the ReShade runtime. (3) accept any window level: borderless "full screen" windows sit above level 0.
Overlay and effect toggle are global Carbon hotkeys (no extra permission) that call `macshade_bridge_set_overlay` / `_toggle_effects`, applied on the rendering thread. While the overlay is open the window takes mouse and keyboard, afterwards the game is activated again.
Verified with the unmodified Spider-Man: Edge of Time recomp (no injection), a test window (windowed, macOS full screen, level-25 borderless) and hotkeys sent as system key events. Not verified: real keyboard, mouse interaction with the menu, exclusive full screen (display capture), the Screen Recording permission of a signed MacShade.app (tests ran under the terminal's permission).

## Minimum macOS of the injected library
`libmacshade.dylib` is loaded into games and must load on every macOS the app supports (13 and later). It used to be built with the host's SDK and deployment target (macOS 27), so releases 0.1-0.4 failed to load below macOS 27 (status 1, "built for macOS 27 which is newer than running OS"). `mac/CMakeLists.txt` now sets `CMAKE_OSX_DEPLOYMENT_TARGET 13.0` and makes unguarded newer APIs an error for the Objective-C++ files. Floating-point `std::from_chars`/`to_chars` (macOS 26 / 13.3) were replaced by `strtof`/`snprintf` in ReShade's effect lexer and GLSL/HLSL codegen. Check a build with `vtool -show-build <dylib>` (minos 13.0). Not tested on a real older macOS.

## Screen filter: half resolution
`captureHalfResolution` (Performance tab, off by default) passes `--scale 0.5` to the helper, which asks ScreenCaptureKit for half the pixel size; the window shows it enlarged. Measured only with a test window (1470x956 instead of 2940x1912 frames processed), no FPS numbers.

## Screen filter: geometry and diagnostics (0.4.3)
Report: on a Mac mini with an external monitor the picture was about 96 % of the screen, anchored bottom left, and clicks landed beside the buttons (full screen via the green button and via the game). Cause not found; not reproduced. Changes: the overlay window no longer lets AppKit move or shrink it (`constrainFrameRect:toScreen:`), the frame is cropped to `SCStreamUpdateFrameContentRect` when ScreenCaptureKit reports margins, and the log now has the game window, wanted and actual overlay frame, all screens with scale, the captured frame size and a 10 s summary (frames in/shown/dropped, ms per frame). `MACSHADE_FILTER_DEBUG=1` additionally logs the frame attachments once. Effects switched off with the effects hotkey did not slow the filter down in a test (58 fps, 3.4 ms per frame).

## Screen filter 0.4.4: pipeline, bypass, hotkeys, geometry log
- **Pipeline** (`MACSHADE_PIPELINE`, set from the game's "smooth frame rate" option): three ring surfaces; frame n is copied (not awaited), n-1 goes to ReShade (`macshade_bridge_pipeline_submit`), n-2 is shown. When the capture is quiet the last frame is fed again up to three times so the pipeline empties. Measured on a GPU-bound scene: no reliable gain (about 20 to 23 fps); the copy waits for the GPU behind the game (8-30 ms), ReShade itself needs 2-7 ms.
- **Idle bypass**: when `runtime::is_idle` (effects off, menu closed) the capture is stopped and the overlay hidden, the game runs unfiltered; a hotkey ends it (`MACSHADE_FILTER_NO_BYPASS=1` disables it).
- **Hotkeys** (menu, effects, screenshot) are system-wide Carbon hotkeys, registered only while the game (or the helper, menu open) is frontmost. The screenshot key asks ReShade's runtime for its own screenshot (`runtime::request_screenshot`), named after the game.
- **Geometry**: attachments are read through the SDK constants; every change of surface size, bounding/content rect, contentScale, scaleFactor and screenRect is logged, as is the capture size (`pointPixelScale` on macOS 14+, else the screen's backing scale). Reported but not found: picture 96 % of the window on a Mac mini with an external monitor.
